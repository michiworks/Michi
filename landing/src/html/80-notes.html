Questions people ask first.

Is this another multi-agent orchestrator?

No. Orchestrators split one task across agents that report back and end. In Michi you open each branch yourself, keep talking to it for as many rounds as it needs, and decide what comes back. It can run on the same agents.

Does a branch create a git branch or a worktree?

No. A branch is a conversation, not a checkout. Every branch works in the same project folder, so Michi doesn’t isolate code changes.

What does a branch know?

Everything above the sentence you branched from, plus anything you @-mention. Nothing leaks back up until you merge it or @ it.

Does merging change the branches?

No. Merge starts a new thread from the branches you picked. The originals stay exactly as they were.

Where does my data live?

In a SQLite database on your Mac. You don’t need a Michi account to run it locally. Each agent still talks to its own provider.

Why not a new chat, or tmux?

A new chat starts from nothing, and a tmux split is another terminal. A branch starts with the exact context it came from, and Michi keeps the whole tree.

What does Memory keep?

Only the notes you ask for or approve: preferences, facts, decisions and conventions, for every workspace or just one. They’re stored with your chats on your machine, every agent reads them, and you can change or delete any of them in Settings.

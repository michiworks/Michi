## Rules

Notation. Durations, curves, springs and the `TRANSITION` presets are the motion tokens of tokens.md TK-29 (durations) and TK-30 (curves and springs); motion.md MO-05 assigns them per element type. Rules here name them as the code writes them (`--t-enter`, `DUR.collapse`, `EASE.drawer`, `TRANSITION.collapse`, …) and give the value in ms where the rule depends on it. "Fresh" and "settled" follow motion.md MO-01 (`FRESH_MS`, `frontend/src/motion/useFresh.ts`). "Reduced motion" means either trigger, the OS setting or Settings › Reduce motion (motion.md MO-14; `frontend/src/hooks/useReducedMotion.ts`).

### TR-02 Restored content renders settled; only fresh items enter

**Rule.** Follow motion.md MO-01. For surfaces it means: content that mounts because of hydration, a reload, a remount, a lazy chunk, a tree, scope or page switch, a reopened pane or "Show N more" paging renders its final state in the first frame (`AnimatePresence initial={false}` or a settled first render); only an item created while its container is on screen plays its entrance. Decide freshness once, on first render, with `isFresh` / `useFresh` and `FRESH_MS` imported from `frontend/src/motion/useFresh.ts`; never declare another 1000 ms window.

**Sources.** [RF] "Often state transitions accidentally play out when the page loads, but this makes the application feel poorly built." [LIN] "No longer animates in similar issues if they are available immediately on navigating to an issue." [CODE] "renders hydrated history settled and plays the entrance only for a send made while it is open" (`frontend/src/components/terminal/PaneMessageList.motion.test.tsx`). [CODE] "opening the map never animates the existing tree — only nodes that show up afterwards (agent spawn / branch) grow in." (`frontend/src/components/terminal/pages/Map.tsx`).

**Michi today.** 24 of 50 `<AnimatePresence>` sites pass `initial={false}`; the other 26 wrap a child that mounts only when opened (menus, dialogs). Freshness: 8 direct `useFresh` / `isFresh` calls, plus `isFreshMessage` (1) and `isFreshBranch` (4); `frontend/src/components/terminal/spaces/home/HomeDocument.tsx` imports `FRESH_MS` (census at f578af740). Canonical: `frontend/src/motion/useFresh.ts` `isFresh`, `frontend/src/components/terminal/agentBlockMotion.tsx` `Reveal` / `RevealList` / `RevealOnShow`. Exceptions: `frontend/src/components/terminal/branchMotion.ts` declares its own `FRESH_MS = 1000`; `.t-pre-block` (`fadeIn var(--t-enter)` in `frontend/src/index.css`) replays on every mount (merge-sources notice, runtime warning, comment chips, queued blocks).

**Check.** Tests: `frontend/src/components/terminal/PaneMessageList.motion.test.tsx`, `frontend/src/components/terminal/BranchRow.test.tsx` ("renders a hydrated row settled, with no wrapper, wash or drawing rail"), `frontend/src/components/terminal/DiffReceipt.test.tsx`, `frontend/src/components/terminal/content/db/views/BoardView.motion.test.tsx` ("draws a regrouped board settled: no card arrives, no count rolls"), `frontend/src/components/terminal/spaces/home/HomeDocument.reveal.test.ts`. For a new list, `rg -nP "<AnimatePresence(?![^>]*initial=\{false\})" <file>` returns nothing unless the child mounts only on open. `rg -n "\bFRESH_MS\s*=" frontend/src --glob '!*.test.*'` lists only `frontend/src/motion/useFresh.ts` and the `frontend/src/components/terminal/branchMotion.ts` exception. Devtools: reload a pane with history; the Animations panel records nothing except loops.

### TR-03 A closing surface stops being live at once; nothing waits for its exit

**Rule.** Follow motion.md MO-09 (the leaving element is inert at once; input acts immediately). For surfaces it means: in the same commit, make the leaving layer `inert`, `aria-hidden` and click-through (a "ghost"), drop it from Esc and Back routing (`data-escape-layer` removed), and return focus to its opener — unless the close is a choice that moves focus to its destination (a ⌘K pick, TR-07; a phone-drawer destination, TR-24; a destination opened from a drawer, TR-39). Then let the exit play on the ghost and unmount it at the logical end (transitionend, `onExitComplete` or the primitive's timeout), never after a spring's settling tail. The one sanctioned wait is a menu's 160 ms confirm blink (TR-12).

**Sources.** [OWNER] decision 2026-11-14 (TR-Q1): all like the right-click menu, growing and fading in, fading out to leave. [OWNER] decision 2026-11-14 (TR-Q5): close in one frame when the user opens a target from it. [HIG] "don’t make people wait for an animation to complete before they can do anything" [HIG] "you shouldn't wait for the settling duration for user-facing changes." [WCAG 2.4.3] "When the dialog is dismissed, focus returns to the button or the element following the button." [CODE] "returns focus at close and leaves only an inert ghost while the panel fades out" (`frontend/src/components/ui/ModalShell.test.tsx`); [CODE] "closes the narrow drawer at once when a destination inside it is chosen" (`frontend/src/components/terminal/Sidebar.test.tsx`).

**Michi today.** Every exit-animating primitive does this: `ModalShell` (`ModalLayers` `leaving`), `DrawerShell` (`EXIT_TIMEOUT_MS` 220 ms fallback), `BottomSheet`, `GrowingSurface`, `Lightbox` (static copy), `MobilePaneSwitcher`, `NarrowSidebarOverlay` (drops `data-escape-layer`), `Reveal` bodies, the `useLineDrawer` ghost, `usePanePresence` (exit + 32 ms deadline). Not yet: `ActionMenu`, `DbPopover`, `MichiMenu` and the five single popovers keep their document listeners and their Back layer (`useBackLayer(true, …)`) for as long as they are mounted, which holds only while they unmount in one frame; once they fade out (TR-13) they gate them on `useIsPresent()`, as `DesktopContextMenu` (`frontend/src/components/ContextMenu.tsx`) does. Tests: `frontend/src/components/ui/BottomSheet.test.tsx` ("returns focus at close and drops away as an inert ghost that is no longer a dialog"), `frontend/src/components/ui/DrawerShell.test.tsx`, `frontend/src/components/ui/Popover.test.tsx`, `frontend/src/components/terminal/Lightbox.test.tsx`, `frontend/src/components/terminal/MobilePaneSwitcher.test.tsx`, `frontend/src/components/terminal/Sidebar.test.tsx`.

**Check.** In a unit test, close the surface and assert in the same tick that `document.activeElement` is the opener (or the chosen destination) and the leaving node has `inert` and `aria-hidden` (pattern: `frontend/src/components/ui/ModalShell.test.tsx`). `rg -n "onExitComplete" <file>` shows no focus return or follow-up action deferred to the exit callback.

### TR-04 Every toggle reverses from where it is

**Rule.** Follow motion.md MO-09 (a CSS transition, a motion animation, or WAAPI that commits its current styles; never a `@keyframes` enter/exit pair on something toggled). It applies to every TR-01 surface the user can toggle again before its transition ends: menus, dialogs, drawers, sheets, disclosures, the docked sidebar, panes, the phone toolbar panel and the ⌘J panel. Ten rapid toggles end in the last requested state with no stuck ghost.

**Sources.** [EK] "prefer CSS transitions over keyframe animations since they are interruptible and animate smoothly to the new, updated value." [OWNER c:9o] (recorded outcome) (in Chinese, translated: pressing ⌘J mid-animation reverses from where the panel is) [CODE] "turns one chevron and opens/closes the body, reversing when clicked mid-way" (`frontend/src/components/terminal/MessageBlock.test.tsx`); [CODE] "hands a running entrance over to the exit where it got to" (`frontend/src/components/ui/Popover.test.tsx`).

**Michi today.** Canonical: `frontend/src/components/ui/DrawerShell.css` `.drawer-shell-panel` (a `transform` transition), `GrowingSurface`, `Reveal`, `useLineDrawer` (FLIP with `composite: 'add'`), `usePaneLayout` (E2E "rapid retarget, user interruption, reopen and reduced motion" in `e2e/specs/pane-motion-performance.spec.ts`). The one toggled keyframe pair is the phone narrow toolbar panel (`frontend/src/components/terminal/mobile.css` `mobile-arrive` / `mobile-leave`; its target is in TR-01).

**Check.** `rg -n "animation:\s*[\w-]+ var\(--t-(enter|exit|soft|decay)" frontend/src --glob '*.css'` (19 hits, census at f578af740): no new hit may be the enter or exit half of a keyframe pair on something the user can toggle; the known pair is the `frontend/src/components/terminal/mobile.css` toolbar. Manual: toggle the surface ten times with key repeat; it ends in the last state.

### TR-05 One motion for keyboard and pointer; input changes only origin and dwell

**Rule.** Follow motion.md MO-03. A surface opened from a shortcut (⌘K, ⌘B, ⌘J, ⌘⇧A, Shift+F10) plays the same transition as when it opens by pointer. Input changes only: the transform-origin (the press point for a pointer, the anchored corner for a key; `frontend/src/components/ui/Popover.tsx` `lastPress`), the tooltip dwell (keyboard focus shows a tip at once, TR-14), and a highlight moved by arrow keys: it jumps (`scrollIntoView({ block: 'nearest' })`); its background may fade over at most `--m-hoverMs` (100 ms, `frontend/src/components/ui/Menu.css`), the existing exception in MO-02.

**Sources.** [OWNER c:9m] (recorded decision) (in Chinese, translated: ⌘K: the scrim fades in over 180 ms and the panel goes from opacity 0 and scale 0.96 to 1 over 180 ms) [CODE] "grows from its anchored corner when the keyboard opened it after a click elsewhere" (`frontend/src/components/ui/Popover.test.tsx`). [EK] "These actions may be repeated hundreds of times a day" [RF] "Sometimes we can get away with not animating mouse or keyboard interactions, without it feeling jarring." **Conflict:** Emil says keyboard-initiated actions should never animate ([EK] "You should never animate them."), and Rauno removed motion from keyboard-driven lists ([RF] "I removed motion from core interactions and suddenly felt like I was moving much faster"); M3 and Apple state no keyboard rule. **Choice:** one motion for both inputs. **Why:** the owner chose an entrance for the keyboard-first ⌘K palette (c:9m), the menu tests assert keyboard-opened growth, entrances stay ≤ 180 ms with no exit where the user lands somewhere (TR-07), and no hard requirement is at stake.

**Michi today.** No primitive branches its timing on input type (census at f578af740). `ContextMenu`, `MentionEditor`, `CommandPalette` and `ModelCombobox` move the highlight with `scrollIntoView({ block: 'nearest' })`; inside `.michi-menu` the row background fades over `--m-hoverMs` (100 ms) without moving, elsewhere `.ui-menu-item` over `--t-quick`; `HoverTip` shows on keyboard focus at once (`lastInputWasKeyboard`).

**Check.** `rg -n "lastInputWasKeyboard|lastInputWasTouch" frontend/src --glob '!*.test.*'` stays limited to origin and dwell decisions; a new surface adds no keyboard-only duration (`rg -n "fromKeyboard|byKeyboard" <file>` returns nothing). Devtools: hold ↓ in a long menu; the Animations panel records no transform.

### TR-06 Modal dialogs: ModalShell, motion 'standard'

**Rule.** When a task interrupts the page (a confirmation, an editor, a viewer, a settings window), use `ModalShell` with the default `motion='standard'` (timings: motion.md MO-20): scrim opacity 0→1 over 180 ms (`SCRIM_IN`), panel opacity 0→1 and scale .96→1 over 180 ms on cubic-bezier(0.2,0.8,0.2,1) (`PANEL_IN`); exit 110 ms `EASE.out` with the panel settling to scale .98 (`TRANSITION.exit`). For the exit to play, keep the shell mounted with `open={false}` or remove it inside `<AnimatePresence>`. When one modal hands over to the next, let `ModalShell` hold the scrim at full strength and bring the new panel in with `PANEL_SWAP_IN` (60 ms delay, 160 ms). Reduced motion keeps the fades and drops the scale. Use `motion='none'` (no caller today) only for a dialog that must neither animate in nor leave a ghost: it opens and closes on the spot. A dialog whose content is destroyed at close (`RemoteAuthenticationDialog` ends its sign-in terminal session) instead unmounts outside `<AnimatePresence>`, keeping the entrance and dropping the exit on purpose, with a comment saying why; every other dialog keeps its exit.

**Sources.** [OWNER c:h2] (in Chinese, translated: I find this dialog beautiful) [OWNER c:h3] (in Chinese, translated: I meant its style and effect, which the record lists as including a fade with a slight zoom, reversed on close) [OWNER c:9m] (recorded decision) (in Chinese, translated: Settings closes: opacity to 0, scale back to 0.98, 110 ms ease-out) [RF] "transition-all duration-180 ease-out" (Devouring Details dialog panel). [M3] "If a fade is needed, like with a Dialog entering in the middle of the screen, the fade should use a short duration" [LIN] "The backdrop of the fast creation modal now fades in correctly" [CODE] "hands over to a modal opened a moment after the first closed, and not to one long open" and "opens and closes on the spot with motion="none"" (`frontend/src/components/ui/ModalShell.test.tsx`); [CODE] "No fade-out: closing ends the sign-in terminal session at once" (`frontend/src/components/RemoteAuthenticationDialog.tsx`). **Conflict:** Emil's dialog demo runs 200 ms from scale .9 ([EK] "scale(0.9) preserves the illusion that the element was always nearly there"), his duration band puts modals at 200–300 ms ([EK] "Modals, drawers | 200-300ms"), and Google's material-web dialog slides in over 500 ms ([M3] "{duration: 500, easing: EASING.EMPHASIZED}"). **Choice:** keep 180 ms in / 110 ms out from .96. **Why:** majority (21 of 22 dialog sites) and the owner-approved look; it matches Rauno's 180 ms dialog and breaks no hard requirement.

**Michi today.** 21 of 22 `<ModalShell>` sites use `'standard'`, 1 `'enter'`, none `'none'` (census at f578af740). Canonical: `frontend/src/components/ui/ModalShell.tsx` `PANEL_VARIANTS`, `handOver`, `SAME_MOMENT_MS`. Exceptions: `CreateSpaceDialog` (defined in `frontend/src/components/terminal/spaces/SpacesPage.tsx`) is mounted with `&&` outside `<AnimatePresence>` in `frontend/src/components/terminal/TerminalShell.tsx` and `frontend/src/components/terminal/spaces/home/WorkspaceHome.tsx`, so its exit never plays; `frontend/src/components/RemoteAuthenticationDialog.tsx` drops its exit on purpose ("No fade-out").

### TR-41 When a hard cut is the correct choice

**Rule.** Use a one-frame change, with no transition, when: (1) content is restored, hydrated, remounted or paged in (TR-02); (2) the user switches page, route, tab, view, workspace or tree (TR-26); (3) results update per keystroke or per poll (palette, filters, menus, searches); (4) values tick (clocks, relative times, line-chrome counts); (5) a keyboard highlight or a selection moves: it jumps, and only its background may fade, over at most `--m-hoverMs` (100 ms) (TR-05); (6) the ⌘K palette, the phone sidebar drawer or a `DrawerShell` drawer closes because the user picked where to go (TR-07, TR-24, TR-39); (7) the window crosses a layout breakpoint (TR-37); (8) a drag-resize or other direct manipulation tracks the pointer, or a drop in a list lands (TR-21, TR-42); (9) a status word or glyph is replaced: the outgoing one goes at once or within 120 ms while only the incoming one animates (TR-34); (10) a row that hosts a ⋯ kebab changes its hover fill; (11) a passive banner, note, inline panel or the find bar appears (TR-17); (12) reduced motion asks for it (TR-40); (13) an existing pane reopens on a phone (TR-22); (14) the palette or accent changes (TR-38); (15) a disclosure that TR-18 does not list opens or closes: its rows appear or go at once and only its › turns (TR-19). Anything else that enters, leaves or resizes takes the transition of its primitive (TR-01).

**Sources.** [OWNER] decision 2026-11-14 (TR-Q5): close in one frame when the user opens a target from it. [OWNER] decision 2026-11-14 (TR-Q6): only tool blocks, change lists and long messages do this; the rest appear in one frame with the › turning 90°. [M3] "If pure efficiency is a top priority, like opening a menu in a productivity app, a jump cut may be preferred." [EK] "Remove animations or hover interactions altogether if they are seen tens, maybe even hundreds of times a day." [RF] "The overlay never animates which makes moving between apps feel snappy" [HIG] "In apps, generally avoid adding motion to UI interactions that occur frequently." [WIG] "Only animate when it clarifies cause & effect or when it adds deliberate delight" [CODE] "No transition: the fader's solid --term-alt strip must appear in lockstep with the row's own bg flip" (`frontend/src/index.css` `.row-kebab`).

### TR-42 Drag to reorder or move: siblings stay put in lists, the board shuffles

**Rule.** When the user drags an item to a new place:
- The item follows the pointer 1:1 with transitions off (motion.md MO-09).
- In a list, tab strip or document (Pages blocks, sidebar workspaces, pane captions and tabs, a database view's sort rules, calendar events), siblings stay where they are: the dragged item dims (Pages blocks to opacity .45, `.michi-doc-block[data-dragging='true']`), a 2 px accent drop line marks the target (`.native-page-drop`, `.michi-doc-drop`), and the drop lands in one frame.
- On a card board, copy `BoardView`: dnd-kit moves the siblings by transform (its default 200 ms ease), the carried card settles into place over 180 ms on `EASE.drawer` (`DROP`), and a card that changes column flies on `SPRING.soft` (`CARD_MOTION`).
- A drop outside any target, or an edit the backend refuses, returns the item to where it started (the board puts focus back with it, `land`).
- Under reduced motion the drop settle is skipped (`dropAnimation={reduced ? null : DROP}`) and siblings jump.
- Every drag also has a single-pointer path that needs no dragging (WCAG 2.5.7, AA): Move up / Move down in the item's menu (Pages blocks, `frontend/src/components/terminal/content/page/BlockFrame.tsx`), or the field that decides the position (a board card's column, a calendar event's date) edited in its row. ### TR-43 Non-modal surfaces never hide the focused element

**Rule.** When a non-modal surface overlaps content that can take keyboard focus (a `modal={false}` DrawerShell, the Companion panel in the phone layout, the notice stack and toasts, the find bar, the selection popup, the pane arrivals tab), it must never entirely hide the focused element (WCAG 2.4.11, AA). Use one of: (a) reflow the content beside it (the docked Companion panel, a docked side column); (b) close on Esc and when focus moves into content it covers (menus, popovers and `HoverTip` already close on blur); (c) step aside while a covered region has focus (the notice stack's `data-aside`); (d) take focus, make the covered content `inert` and return focus at close, as a modal does — use sparingly. A new region that sits under the top-right corner (a composer, a find bar, a toolbar) marks itself `data-notice-avoid`.

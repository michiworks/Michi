### ST-01 Component state matrix

**Rule.** When you build or restyle an interactive element, use the primitive in the first column and give each state the value in its row. When no primitive fits, copy the row's values onto your own class. Hover values apply inside `@media (hover: hover)` (ST-02): a hover cell marked "gated" is already inside the gate, and every other hover cell is ungated today. A cell that names a rule defers to it. Unmarked cells are the primitive's current rule; cells marked "(target; today …)" are the converged value, and when you edit that primitive you bring it to the target.

### ST-02 Hover is for real pointers only

**Rule.** When a rule changes anything on `:hover`, put it inside `@media (hover: hover)`; `(hover: hover) and (pointer: fine)`, used by Settings and the composer chips, is also fine. CSS written as strings inside TSX or TS (`frontend/src/components/terminal/pages/Profile.tsx`, `frontend/src/components/terminal/pages/docLayout.ts`) follows the same gate. Outside the gate, give `:active` its press fill, the hover fill or, on a ghost control, one step darker (ST-06), so a tap still shows a press. When hover shows, hides or moves content, also follow ST-04. When you edit the hover of a shared primitive (`.ui-btn`, `.ui-menu-item`, `.t-icon-btn`, `.t-text-btn`, `.t-row-hover`, `.ui-overlay-close`), move it into the gate.

### ST-03 What hover changes

**Rule.**
- When a control or row lights on hover, use `background: var(--term-hover-bg, var(--term-alt))`. On translucent glass (card-mode sidebar rows, the Settings window), use `var(--sb-card-hover)`; on the dark floating bars, `var(--sel-bar-hover)`.
- When its resting text is `--term-mid` or `--term-muted`, also step the text to `--term-fg`.
- When the hovered element is a card, change `border-color` to `--term-line-s` instead of filling it; a card that opens something also takes the level-1 shadow (`--term-composer-shadow-muted`, tokens.md TK-24).
- Hover never scales a row, menu item or chip, never adds a shadow to a row or chip (the owner's `.mention-chip` glow is the one exception, tokens.md TK-07), never changes font-weight (ST-23), and never lowers the contrast of the label, the focus ring or a selection marker (ST-30).
- A disabled control has no hover: write `:hover:not(:disabled)` and, for `aria-disabled` controls, `:not([aria-disabled='true'])`.
- Transition named properties only, never `transition: all`. Durations: motion.md MO-02.

### ST-20 Keyboard semantics

**Rule.**
- Use `<button type="button">` for actions and `<a href>` for navigation.
- A row whose whole surface acts and that holds other buttons: a full-row `<button>` whose stretched `::after` covers the row, with sibling action buttons above it (`z-index: 1`), as `frontend/src/components/terminal/pages/settings/history.css` `.settings-history__open` does. - Menu triggers: `aria-haspopup="menu"` and `aria-expanded`; menu keys as in ST-10.
- Toggles: `aria-pressed`. Switches: `role="switch"` + `aria-checked`. Options: `aria-checked` or `aria-selected`. The current item: `aria-current`.

- Lists with a highlight: ↑/↓ move one highlight that the mouse shares, drawn as `[data-active='true']` with the hover fill. A mouse that has not moved does not take the highlight.
